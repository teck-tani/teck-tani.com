# teck-tani.com 일평균 $10~15 성장 실행안

작성일: 2026-09-20 KST. 사용자 요청에 따라 AdSense를 읽고 정리한 로컬 계획이다. 목표는 AdSense 예상 수입 기준이며 운영비를 차감한 순이익은 아니다. 아래 주차는 작업 순서이고 수익 달성 기한을 보장하지 않는다.

## 1. 직접 확인한 기준선

AdSense의 사이트별 보고서에서 `teck-tani.com` 행을 확인했다. 보고서 이름에는 ‘최근 30일’이 들어 있지만 실제 선택 기간은 아래 날짜다. 오늘 진행 중인 수익은 제외했다. 일평균은 합계 ÷ 실제 일수로 계산했으며, 사이트 분류 표의 ‘평균’ 행을 일평균으로 사용하지 않았다.

| 지표 | 최근 28일: 8/23~9/19 | 최근 7일: 9/13~9/19 |
|---|---:|---:|
| 예상 수입 합계 | $45.91 | $8.87 |
| 일평균 예상 수입 | $1.64 | $1.27 |
| AdSense 페이지뷰 | 11,482 | 3,003 |
| 일평균 페이지뷰 | 410 | 429 |
| 페이지 RPM | $4.00 | $2.95 |
| 광고 노출수 | 61,497 | 16,529 |
| 노출 RPM | $0.75 | $0.54 |

28일 계정 전체 수익은 $46.41이다. 이 중 약 98.9%가 본사이트 수익이므로 위 목표는 본사이트에 집중해 계산했다. AdSense 예상 수입은 확정 지급액과 다를 수 있다.

28일에서 최근 7일을 뺀 앞선 21일(8/23~9/12)은 $37.04, 8,479 PV다. 일평균 $1.76, 404 PV, 페이지 RPM 약 $4.37이다. 이에 비해 최근 7일은:

- 일평균 PV **6.3% 증가**
- 페이지 RPM **32.4% 하락**
- 일평균 수입 **28.2% 감소**

최근 수익 감소에는 페이지뷰당 수익 하락이 나타나 있다. 국가·기기·유입 경로·페이지 구성·광고 배치·광고 수요 중 무엇이 원인인지는 아직 확인하지 못했다. 광고 노출/PV는 약 5.30에서 5.50으로 늘었지만, 이 비율은 화면에 동시에 놓인 광고 수를 뜻하지 않는다.

출처: 2026-09-20 로그인된 [AdSense 보고서](https://adsense.google.com/adsense/) UI 직접 조회. 조회 필터 외 광고 설정·저장된 보고서는 변경하지 않았다.

## 2. 목표에 필요한 규모

`일수익 = 하루 AdSense 페이지뷰 × 페이지 RPM ÷ 1,000`

| 일평균 수익 목표 | 페이지 RPM $2.95 유지 | 페이지 RPM $4.00일 때 |
|---|---:|---:|
| $3 | 약 1,017 PV/일 | 약 750 PV/일 |
| $5 | 약 1,695 PV/일 | 약 1,250 PV/일 |
| $10 | 약 3,390 PV/일 | 약 2,500 PV/일 |
| $15 | 약 5,085 PV/일 | 약 3,750 PV/일 |

현재 429 PV/일을 기준으로 최근 RPM이 유지되면 약 8~12배의 PV가 필요하다. RPM이 $4 수준이면 약 6~9배다. 유입 규모와 구성에 따라 RPM도 바뀌므로 이는 시나리오 계산이며 예측이 아니다. GA4 페이지뷰와 AdSense 페이지뷰를 같은 값으로 취급하지 않는다. [Google 페이지 RPM 정의](https://support.google.com/adsense/answer/112030?hl=ko)

## 3. 색인 상태의 해석

[기존 색인 기록](./구글-색인-현재상태.md)은 이전 PC에서 전달된 기준선이며 이번에 GSC를 재측정한 값은 아니다.

- 본사이트 sitemap 기준 색인 1 / 미색인 161 / 총 162. 페이지 보고서 자료일은 9/14.
- 홈페이지는 색인 유지, Base64·JSON 두 실험 URL은 ‘크롤링됨 - 현재 색인이 생성되지 않음’.
- 두 실험 URL은 가져오기 성공, 크롤·색인 허용, 자기 canonical. 9/18 일반 검색 Googlebot의 HTTP 200 방문이 검증된 기록이 있다.
- 따라서 전체 사이트가 차단됐다고 보거나, 9/18 방문을 Google의 최종 거절로 해석할 근거는 없다. 크롤링 성공과 색인 완료도 다르다.

[기존 점검 일정](./구글-색인-점검일정.md)에 따라 9/21~26 관찰, 9/27 미색인 지속 시 심화 진단, 10/4 평가를 진행하는 계획을 유지한다. 예약의 활성·담당 작업 연결은 기존 문서에서도 미확정이며 이번에 재확인하지 않았다.

Google은 재수집 요청이 색인을 보장하지 않으며 같은 URL을 반복 요청해도 빨라지지 않는다고 안내한다. 작업은 관찰·진단과 실제 사용자 유입 확대를 병행한다. [Google 재수집 안내](https://developers.google.com/search/docs/crawling-indexing/ask-google-to-recrawl)

### P0/P1: 주력 도구 선정과 개선

실제 주력 도구는 아직 확정하지 않았다. AdSense Top pages에는 트래픽이 적은 행을 제외한다는 안내가 있었고, 이번 조회에서 페이지별·유입 경로별 세부 표를 확보하지 못했다. 표시되지 않는 것을 수익 0으로 보지 않는다. GA4 인기 랜딩 페이지·유입 경로·작업 완료 자료를 다음 판단에 사용한다. [페이지 URL 보고서 안내](https://support.google.com/adsense/answer/11988478?hl=ko)

다음은 데이터 확인 전 후보이며 검색량·수익성 검증 결과가 아니다.

| 후보 작업 묶음 | 구체적인 사용 사례 | 확인할 개선점 |
|---|---|---|
| 이미지 압축 → 리사이즈 → 변환 | 제출할 사진을 지정 용량·크기에 맞추기 | 목표 용량 달성 여부, 화질, 모바일 다운로드, 필요한 다음 작업 연결 |
| 전자서명·도장 → JPG/PDF 도구 | 문서에 넣을 투명 배경 서명 이미지를 만들기 | 출력 배경·해상도, 사용 방법, 후속 작업 안내 |
| 글자수 → 텍스트 정리 | 제출 글의 글자수와 공백을 정리하기 | 계산 기준, 복사 편의, 재방문 동선 |
| JSON·Base64 등 기존 개발 도구 | 실제 개발 중 발생하는 변환·검증 작업 | 현재 유입·반복 사용 여부, 데이터 보존과 오류 처리 |

현재 공개 이미지 압축 페이지에는 이미 목표 용량·일괄 처리·사용법·관련 도구가 있고, JSON 페이지에는 입출력 예제와 한계 설명이 있다. ‘설명이 없으니 글을 더 쓰자’로 접근하지 않는다. 실제로 잘 작동하는지 확인하고 부족한 부분만 보강한다. JSON·Base64는 색인 실험 대상이라는 이유만으로 수익 주력으로 선정하지 않는다. [이미지 압축 페이지](https://teck-tani.com/ko/image-compressor), [JSON 페이지](https://teck-tani.com/ko/json-formatter)

측정이 없다면 `tool_start`, `tool_success`, `download`, `related_tool_click` 같은 행동 이벤트를 설계한다. 파일·텍스트·서명 내용은 분석 이벤트에 담지 않는다. 완료율은 완료 이벤트가 발생한 세션 ÷ 도구 시작 세션 등 일관된 기준으로 정의한다.

### P1: 색인 대기 중에도 할 수 있는 유입 작업

- 기존 유입 경로가 확인되면 그 경로의 상위 도구부터 확대한다.
- 네이버·Bing의 현재 등록·수집 상태를 확인하고 누락된 설정만 보완한다. 등록 자체가 색인·유입을 보장하지 않는다.
- 주력 도구 3개에 실제 작업 예시가 있는 안내를 각 1개 준비한다. 예: ‘사진을 100KB 이하로 맞추기’, ‘투명 배경 서명 이미지 만들기’. 가능 여부와 결과를 먼저 검증한다.
- 가장 관련 있는 채널 하나에서 2주간 시험한다. 블로그·짧은 시연 영상·주제에 맞는 커뮤니티 중 관리할 수 있는 채널을 고르고, 외부 링크에는 채널별 UTM을 붙인다.
- 다른 운영 사이트에서는 사용자의 다음 작업과 관련 있는 위치에만 연결한다. 관련 사이트의 트래픽이 이미 크다고 가정하지 않는다.
- 게시물 수보다 실제 도구 사용자·완료율·재방문·수익 기여를 본다. 사용자가 오지 않으면 기능을 더 만들기 전에 소개 위치와 사용 사례를 바꾼다.

참고: [네이버 서치어드바이저](https://searchadvisor.naver.com/start), [Bing 사이트맵 안내](https://www2.bing.com/webmasters/help/sitemaps-3b5cf6ed).

### P1/P2: 광고 실험과 확대

먼저 현재 배치와 최근 변경 이력을 파악한다. 이후 자동 광고가 적용돼 있다면 AdSense의 지원되는 비교 실험을 검토한다. 광고 위치·형식 등 한 요소를 비교하며 입력·실행·다운로드를 방해하지 않는지 함께 확인한다. 광고 CTR만 높이는 것을 목표로 삼지 않는다. [Google 자동 광고 실험](https://support.google.com/adsense/answer/9726342?hl=ko)

실험별로 시작일, 변경점, 대상, 기준선, 결과를 남긴다. 수익이 늘어도 도구 완료율이나 재방문이 악화되면 유지 여부를 다시 판단한다. 현재 트래픽으로 작은 차이를 빠르게 확정하기 어렵다는 점을 반영한다.

## 7. 후속 확인 — 준비된 신규 메뉴 목록

같은 날 사용자의 추가 요청으로 실제 앱 원격 `teck-tani/dev-program` 읽기에 성공했다. 로컬 앱 체크아웃은 여전히 없지만 원격 문서와 도구 레지스트리는 읽을 수 있다. 삭제된 6/8의 100종 로드맵과 현재 9/1의 테스트 도구 TOP20을 찾아 원본 사본을 보존했다. 두 목록에는 경로 중복·기존 구현·기능 중복이 있다.

추가로 찾은 9/5 운영 기록에서는 당시 Bing·네이버가 수익의 약 84.9%, 반응속도 테스트 하나가 약 51.5%였다. 이는 이번 28일 실측과 다른 기간의 과거 기록이다. 앞서 제시한 이미지·서명·텍스트 후보와 함께, 반응속도 방문자와 연결되는 키보드·마우스·모니터 테스트도 우선 검토할 근거가 생겼다. 후보 3개부터 현재 수요를 검증하고 소규모로 개발·평가하는 방향을 권한다. [120개 메뉴 검토와 출처](./신규-메뉴-120개-검토-2026-09-20.md).
