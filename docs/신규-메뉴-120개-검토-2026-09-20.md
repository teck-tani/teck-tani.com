# 신규 메뉴 약 120개 확장 검토

작성일: 2026-09-20. 이번 작업은 문서 확인과 전략 검토이며 신규 기능을 개발·배포한 결과가 아니다.

## 발견한 목록

사용자가 말한 규모와 맞는 문서 두 개를 찾았다.

1. [신규 유틸 100종 로드맵](./reference/신규-유틸-100종-원본-2026-06-08.md): 2026-06-08 작성. 이미지/미디어 30, 텍스트 22, 생활/재미 20, 개발도구 28. 6/16 문서 정리 커밋에서 삭제됐고 삭제 직전 Git 이력에서 복원했다.
2. [Bing 테스트 도구 TOP20](./reference/빙-테스트도구-20종-원본-2026-09-01.md): 2026-09-01 작성. 48개 후보를 검토했다는 기록과 최종 20개가 있다. 현재 원격 main에도 남아 있다.

두 문서를 합친 120행이 사용자가 기억하는 목록일 가능성이 높다. 별도의 단일 120종 문서가 있다는 사실까지 확인한 것은 아니다. 현재 소개 저장소, 관련 로컬 Markdown, Documents/Downloads와 ZIP 16개, 실제 앱 원격 문서와 관련 삭제 이력을 검색했다.

정확한 원본 경로·리비전은 [출처 기록](./reference/README.md)에 보존했다. 현재 앱 레지스트리는 원격 main `a9976eab3a7a6be2691014c9c53af64627d6b0dd`의 `src/config/tools.ts`를 읽어 비교했다.

## 숫자와 중복

- 100종 마스터 표: 100행. TOP20 표: 20행.
- 경로가 양쪽에서 같은 도구: `keyboard-test`, `browser-info` → 고유 제안 경로 118개.
- 현재 72종 레지스트리와 경로가 같은 도구: `background-remover`, `balance-game`, `qr-scanner`, `video-compressor` → 이 4개를 빼면 114개 경로.
- 114는 아직 정리되지 않은 경로 수다. 다른 이름으로 이미 구현된 기능, 두 목록 사이의 의미 중복, 다른 운영 사이트와의 중복을 더 빼야 최종 개발 목록이 된다.

| 유형 | 예시 | 처리 제안 |
|---|---|---|
| 이미 현재 레지스트리에 존재 | 배경 제거, 밸런스 게임, QR 스캐너, 동영상 압축 | 신규 개발 대상에서 제외하고 필요한 개선만 검토 |
| 두 목록 사이 의미 중복 | `cps-test` / `click-speed-test`, `dead-pixel-test` / `monitor-test` | 한 도구의 범위로 통합 검토 |
| 기존 기능과 겹침 | CPS는 기존 반응속도 테스트에 있음. JSON→YAML·TypeScript도 현재 JSON 페이지에 안내돼 있음 | 별도 URL이 필요한 사용자 이유와 기존 유입 영향을 먼저 검토 |
| 다른 이름으로 유사 도구 운영 | `video-to-audio` ↔ 현재 `mp4-to-mp3`, `mbti-test` ↔ 현재 `personality-test` | 입력 형식·기능 차이를 확인하고 필요한 차이만 개발 |
| 별도 프로젝트와 겹칠 수 있음 | 운세·타로·별자리 | 현재 운세 프로젝트와 중복 검토 |

## 판단

신규 도구 확대는 성장 수단으로 검토할 가치가 있다. 첫 개발은 3개 정도로 제한하고 사용자에게 필요한지, 유입·완료·수익이 생기는지 확인한 다음 확대하는 것을 권한다. 120개는 후보 목록으로 유지한다.

이번에 추가로 찾은 [9월 초 운영 기록](/Users/tani/ops/sites/teck-tani.md)에는 9/5 당시 최근 30일 수익의 약 84.9%가 Bing·네이버였고 반응속도 테스트 하나가 약 51.5%를 만들었다고 적혀 있다. 이는 오늘 다시 측정한 값이 아니다. 그래도 어떤 사용자와 도구가 이미 성과를 낸 적이 있는지 확인할 역사 근거는 된다.

따라서 Google 색인 회복만 기다릴 필요는 없다. 기존 반응속도 테스트 방문자와 목적이 연결되는 도구를 소규모로 시험할 수 있다. 다만 과거 특정 도구의 성과가 비슷한 도구의 성과를 보장하지는 않는다.

120개를 동시에 만드는 데는 기능 검수·번역·모바일 지원·설명 관리가 필요하다. 자동 코드 생성으로 구현 시간이 줄어도 실제 사용 확인과 유지보수는 남는다. 페이지 수 증가만으로 색인이 해결되거나 수익이 비례해 증가한다고 기대할 근거는 없다. Google도 사이트를 새롭게 보이게 하려고 많은 콘텐츠를 추가하는 것 자체가 순위를 개선하지는 않는다고 설명한다. [Google 유용한 콘텐츠 안내](https://developers.google.com/search/docs/fundamentals/creating-helpful-content)

## 첫 배치 후보

아래 순서는 현재 수요·경쟁도 검증 전의 제품 관점 제안이다. 9/1 문서의 순위를 그대로 채택한 것이 아니다.

| 우선 검토 | 후보 | 이유 | 출시 전에 확인할 점 |
|---|---|---|---|
| 1 | 키보드 테스트 | 키 입력·동시입력 확인이라는 목적이 분명하고 기존 반응속도 사용자와 연결 가능 | 현재 검색 수요, 경쟁 도구와 차이, 지원 기기와 입력 제한 |
| 2 | 마우스 테스트 | 버튼·휠·더블클릭 이벤트 확인, 키보드 도구와 함께 이용할 이유가 있음 | CPS와 범위 구분, 근거 없이 하드웨어 고장 확정하지 않기 |
| 3 | 모니터 테스트 | 단색·패턴으로 화면 상태를 살피는 작업이 명확함 | 전체화면·모바일 동작, 광고가 검사 영역을 가리지 않는지 |
| 추가 후보 | 주사율 측정 | 위 도구와 방문층이 가까움 | 브라우저 렌더 주기 추정과 물리 디스플레이 주사율을 구분할 수 있는지 |
| 별도 실무 후보 | 팀·조 편성 | 사다리·룰렛 방문자의 다음 작업으로 연결 가능 | 기존 랜덤 기능에 없는 조건별 편성 등 실제 요구가 있는지 |

첫 배치에서는 CPS 분리를 우선하지 않는다. 기존 반응속도 페이지가 수익 기여 이력이 있는 만큼, 현재 검색어·클릭·기능 사용 자료를 먼저 확보한다. 색각·정신연령 등 테스트는 결과의 근거와 검수 비용을 확인한 뒤 판단한다. 기능 추가만 쉬운 것과 믿을 수 있는 결과를 제공하는 것은 별도 과제다.

## 실행 순서와 확대 기준

1. 전체 목록에 `이미 구현 / 기존 기능 통합 / 독립 신규 / 다른 사이트 소관 / 보류` 상태를 붙인다.
2. 위 후보 3개에 대해 실제 검색 수요·현재 결과 페이지·기존 사용자의 요구를 확인한다. 자동완성 개수는 검색량으로 환산하지 않는다.
3. 통과한 후보부터 개발하고 도구별 공개일과 변경점을 기록한다. 기존 수익 페이지의 URL과 핵심 기능 변경은 별도 판단한다.
4. 도구별 유입, 시작·완료, 다음 도구 이동, 재방문과 가능한 수익 자료를 본다. 공개 직후에는 기능 정상 여부를, 2주 후에는 발견·노출 추세를, 4~6주 후에는 다음 배치 우선순위를 검토한다. 이 기간은 색인·수익 달성 보장이 아니다.
5. 유입이 없으면 검색 발견·노출 문제부터, 방문은 있지만 완료가 적으면 제품 문제부터 진단한다. 성과가 있는 주제 주변으로 다음 3~5개를 확장한다.

현재 실측 기준은 [수익 성장 실행안](./수익-10배-성장계획-2026-09-20.md)의 최근 7일 429 AdSense PV/일, 페이지 RPM $2.95다. 목표 $10~15에는 같은 RPM에서 약 3,390~5,085 PV/일이 필요하다. 신규 메뉴 개수 대신 전체와 도구별 실제 증가분으로 판단한다.

## 기존 문서에서 다시 검증할 주장

- 100종 문서의 ‘현재 62종과 중복 0’은 6월 전제이며 현재 레지스트리는 72종이다.
- ‘초대형 수요’, ‘공급 공백’, S/A 등급에는 현재 사용할 수 있는 충분한 수치 근거가 없다.
- 20종 문서도 자동완성 깊이가 검색량이 아니라고 명시한다. 자동완성이 없는 것을 수요 0으로 단정한 탈락 설명도 재검토해야 한다.
- 현재가 9/20이므로 맞춤법 퀴즈의 ‘한글날까지 색인 한 달 확보’ 전제는 더 이상 성립하지 않는다.
- 일부 도구의 기술·호스팅·측정 정확성 전제와 기존 기능 범위가 달라졌을 수 있다. 원문은 아이디어 자료로 활용한다.
